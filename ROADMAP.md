# Roadmap — Ивритский тренажёр

Список того, что ЕЩЁ НЕ сделано — в отличие от CHANGELOG.md, где то, что уже
сделано. Проверяй этот файл в начале работы, обновляй по ходу (вычёркивай
сделанное — перенося смысл в CHANGELOG, не дублируя тут "уже готово"),
дописывай новое, когда всплывает идея, которую не делаем прямо сейчас.

Файлы планов из `/plan` (`~/.claude/plans/*.md`) сюда не переносятся
автоматически и могут устареть незаметно — если план оттуда упоминается,
сверяй с реальным кодом/CHANGELOG, прежде чем предлагать его как ещё не
сделанный.

См. также [ROADMAP.md читалки](https://github.com/gigstersvideo-stack/hebrew-reader/blob/main/ROADMAP.md)
— сайты связаны, часть идей может касаться обоих сразу.

Отзывы с сайта разбираются в [FEEDBACK_LOG.md](FEEDBACK_LOG.md) —
сверяйся с ним при новой выгрузке отзывов, прежде чем разбирать их заново
(многие уже были устаревшими на момент отправки).

## Открытые пункты

- **Словарная проверка полного написания: этап 2, остаток 79 слов** (2026-09-20) —
  этап 1, `עכשיו` и два прохода этапа 2 сделаны (v1.27.2—v1.27.5): из 820
  слов (1963 вхождения) осталось 79 слов (145 вхождений) по `python

  автоматически не исправились: 63 предложения, где переписанный вариант не
  прошёл проверку (в основном облегчённая модель после исчерпания квоты
  сильных), и около 41 строки теории. Повторить перегенерацию сильной моделью
  после сброса квоты (00:00 UTC, `gemini-3.6-flash`/`3.5-flash`) или разобрать
  вручную: `python audit_corpus.py --dict` печатает список, отчёт в
  `_dict/audit_report.json`. Осторожно: сильная модель тоже ошибается —
  «исправляла» намеренный двойной йод гемминации (`מְסוּייָּם`) и объявляла
  верными слова без йода (`חֵרוּם`, `שֵׁרוּתִים`), поэтому каждый результат
  прогонять через аудит и смотреть глазами.
- **Шэдоуинг** (2026-09-09, из отзыва с сайта) — новый тип упражнения
  «повторить вслух за диктором». Нужно сперва решить формат: с записью
  голоса пользователя и проверкой произношения (тяжело) или просто
  повтор вслух без обратной связи (намного проще) — от этого зависит
  оценка объёма работы.
- **Курс "Корни" — примеры נפעל из реальных новостей** (2026-09-16, из
  отзыва с сайта) — в первом корне (ה-י-ה) много предложений использует
  биньян נפעל, но в самой теории корня про него ничего не сказано;
  пользователь хочет отдельный блок с примерами употребления из реальных
  новостей (не сгенерированных). Не решено: откуда брать новостные тексты
  (авторские права — та же тема, что и в пункте про песни ниже), формат
  блока (сколько примеров, куда в UI теории встраивается), нужен ли
  такой блок для ВСЕХ биньянов/корней или только там, где это особенно
  полезно. Ждёт обсуждения перед оценкой объёма работы.
- **Английский вариант сайта** (2026-09-11) — идея, вероятно касается
  обоих сайтов сразу (тренажёр + читалка связаны), детали (полная
  локализация интерфейса vs просто английские версии карточек/переводов,
  отдельный домен/путь vs переключатель языка) не обсуждали. Ждёт
  обсуждения. См. также пункт в ROADMAP.md читалки.
- Рост библиотеки контента у читалки, см. её ROADMAP.md по ссылке выше.
- **Омографы и слитный предлог+ה с неверным дагешем — нужен внешний
  дикнователь для аудита** (2026-09-18, из внешнего ресёрча при
  консолидации QA) — два класса ошибок никуда, которые механической
  строковой проверкой не поймать: модель выбирает НЕПРАВИЛЬНУЮ (но
  существующую) огласовку омографа по контексту, и/или теряет
  дагеш при слиянии предлога (ב/כ/ל) с артиклем ה. Нужен второй,
  независимый прогон через внешний дикнователь (Dicta Nakdan API или
  похожий) и diff с уже сгенерированным текстом — отдельная
  исследовательская задача (какой сервис, точность, стоимость вызовов),
  не решается в рамках уже сделанного `audit_corpus.py`. Не блокирует
  остальное.
- **Проверка нагрузки + возможный найм** (2026-09-17) — вопрос поднят,
  не решается сейчас: как проверять нагрузку на оба сайта (трафик,
  Firestore-лимиты и т.п.) по мере роста; когда критические баги будут
  закрыты, видимо понадобится кого-то нанять для дальнейшей работы —
  под это нужно оборудование (рабочее место для нанятого человека).
  Ничего не решено по срокам/бюджету/объёму — просто зафиксировано, чтобы
  не потерялось.
